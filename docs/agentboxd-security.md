# Agentboxd security and data handling

## Public demo

The checked static distribution contains the simulated app and inlined standalone. Its build-time mode removes the private inbox transport. It reads its own browser storage namespace. The Pages workflow builds and uploads only the public distribution. Vite has no client environment variable prefix and does not load the private environment directory. The public runtime does not probe localhost or a provider. The distribution check examines file names and bytes, including scripts, styles and any source maps, for configured private values and disallowed endpoints.

The independent proof builds under random synthetic credentials and private mail markers and checks for byte-identical output. Its negative controls place markers in disposable assets and require rejection. The source archive includes the synthetic API fixtures used for testing. Only the public distribution belongs on Pages.

## Private operator

The private backend reads the provider bearer key and selected inbox ID from its runtime environment. Only its typed server-side adapter contacts the provider. The key grants inbox and message reads for a single mailbox. The browser holds a separate local HttpOnly session cookie. The operator obtains access using a file readable by the local OS user. The service binds to IPv4 loopback, validates the request host and origin, requires a custom header on private API requests and serves only the operator build. Use it on a trusted operator machine. Reverse proxies, shared kiosks and remote access require a separately designed authentication and deployment model.

Synchronization is operator-triggered. Provider message and inbox IDs identify each staged record. The staging database keeps processing state across process restarts. Only eligible inbound messages can enter review. The adapter uses provider screening status, request timeouts and bounded responses. It follows documented pagination and respects rate limits. It does not release held mail, bypass screening, acknowledge provider queues, send, delete, fetch links, follow attachments or interpret instructions in content. Text from HTML-only mail is extracted without running it. The UI renders text and attachment metadata as text. Messages too large for safe import cannot become partial donations. ## Imported records and receipts

Import claims one inbox/message pair for one local browser ledger and assigns a stable offer ID. A retry returns to that offer. The original message identity flows through the existing donation parser into the local offer, received lots and packing evidence. Unknown values require review. The staging service holds inbox processing information separately from physical inventory. Only an explicit receipt adds the actual delivered stock. The same recorded receipt cannot add stock twice. Recalculation and candidate switching keep the approved reservations until ordinary approval.

The private browser profile contains the operator’s inventory, approved plans and imported source text. SQLite and the private browser profile both contain private information and depend on the host’s access controls. Browser storage, SQLite and backups are local storage, not application-level encrypted storage. Domain commands involving private mail require writable local storage. The client retries reporting a locally committed review or receipt after an interruption. Keep the original profile and staging data for recovery. Closing a tab or restarting the service does not erase them. Before an explicit operator reset, the app confirms that the staging service has recorded existing physical receipts. A delivery recorded in another tab during reset requires a fresh review of that reset. Starting a new demo is not a substitute for deleting private records from backups. Do not include these locations, live credentials or donor messages in exports, issue reports or screenshots.
